# 다음 디바이스의 작업자에게

## 사용자의 의도

사용자는 구현 항목을 짧게 소개하고 이미지·GIF로 결과를 보여주려 합니다. 본문의 중심은 **직접 부딪힌 문제, 시스템적으로 고려한 점, 협업을 위한 판단, AI의 제안에 의문을 제기하고 방향을 수정한 과정**입니다.

사용자 원문:

> 구현은 짧게 이런거 구현했다 정도로 보여주고 그림과 gif좀 보여주고 할거고, 실질적으로 내가 보여주고 싶은것은 내가 시스템적으로는 어떤것을 고려했고, 협업을 위해서는 어떤것을 고려했고, 하는 것들을 좀 넣고싶어. 구현은 솔직히 니가 다 해주잖아. 실질적으로 내가 부딪혔던 문제들, 내가 했던 고민들, 어떻게 해결방향을 잡았는지, 어떤것을 고려했는지 등을 너와 내가 나눈 대화들을 기준으로 알고싶어.

`src/`, `public/`, 사이트 설정과 배포 설정은 수정 대상이 아닙니다. `docs/`의 이 폴더는 자동으로 프로젝트 페이지에 등록되지 않습니다.

## 다음에 할 일

1. 사용자와 본문에서 강조할 사례를 확정합니다. 우선순위는 구조 단순화 → 콘텐츠 수정 단위 → 소유권·초기화 책임입니다.
2. 기간·팀 규모·역할 명칭·공개할 저장소 또는 실행 링크를 확인합니다. 모르는 값은 추정하지 않습니다.
3. MP4와 GIF를 직접 재생해 사용할 구간과 대표 이미지를 고릅니다. 큰 GIF의 웹용 압축·영상 사용 여부는 게시 단계에서 결정합니다.
4. 질문 이미지를 사용할 때 '대화 원문 재구성' 표시를 유지합니다. 실제 채팅 캡처가 필요하면 별도로 확보해야 합니다.
5. 사이트 반영을 요청받은 뒤 저장소의 `docs/CONTENT_GUIDE.md`와 기존 콘텐츠 구조를 확인합니다. 현재 문서는 게시용 frontmatter가 없는 초안입니다.
6. 코드 근거의 현재 기준은 BFX `1a7d803330923ee6f9f40f5e4bda9e84fb7fab7b`입니다. 이후 코드와 다른 부분은 당시 반영과 후속 변경을 구분합니다.

## 표현 기준

- 코드 작성은 AI 지원을 받았으며, 사용자 기여는 요구 정의·설계 검토·대안 선택·실행 결과 검증으로 구체화합니다.
- '협업 충돌 감소', '제작 시간 단축', '성능 개선'을 측정된 성과처럼 쓰지 않습니다. 수정 단위와 영향 범위를 명확히 하려는 설계 의도로 설명합니다.
- Pixel Crushers Dialogue System은 외부 에셋을 연동·확장한 것입니다. 대화 시스템 전체를 자체 개발했다고 쓰지 않습니다.
- 과도한 추상화를 줄였다는 이유로 모든 상태 추적이 불필요하다고 일반화하지 않습니다. 재접속과 연출 재생 여부에는 별도 상태가 필요할 수 있습니다.
- 구현 요청과 구현 검증은 구분합니다. 질문 이미지 자체는 그 기능이 완성됐다는 증거가 아니라 문제 제기·판단의 증거입니다.
- 지도 프리팹 구성과 경고 처리 사례는 이전 정리에서 보조 근거로 언급됐지만 이번 19개 질문 자료에는 포함되지 않습니다. 추가 근거 확보 전 주요 인용 사례로 확장하지 않습니다.
- 'Dialogue는 조회만 한다' 대신 'Quest가 상태를 소유하며 Dialogue는 공개 API로 조회·변경을 요청한다'고 설명합니다.
- NPC UI 초기화는 최초 직접 호출 이후 완료 이벤트 방식으로 발전했습니다. 현재 Start가 없다고 서술하지 않습니다.
- 래퍼 제거는 삭제 커밋을 찾지 못했고, 알림 누락은 수정·재검증까지 입증하지 못했습니다. 코드 반영이 강하게 확인된 주요 사례와 근거 수준을 구분합니다.
