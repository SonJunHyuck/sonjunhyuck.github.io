# 피드 페이지 1단계 사양 (페이지 형식)

2026-10-21 사용자와 Claude가 합의한 내용이다. 구현은 Codex가 맡고, Claude가 검토한다.
Notion 변경점 자동 게시는 이후 단계이며 이번 범위가 아니다.

## 목적과 범위
- 인스타그램·페이스북·쓰레드처럼 짧은 로그를 시간 역순으로 스크롤해 보는 보기 전용 페이지다.
- 상세 페이지, 좋아요, 댓글, 사이트 내 작성 기능은 만들지 않는다. 자세한 내용은 각 피드의 원본 Notion 링크로 유도한다.

## 위치와 메뉴
- 주소는 `/feed/`.
- 상단 메뉴는 `프로필 / 프로젝트 / 피드 / 개발일지 ↗` 순서. 기존 개발일지(Notion) 링크는 그대로 둔다.
- 사이트맵에 포함한다.

## 데이터 형식
- 피드 하나는 콘텐츠 컬렉션 파일 하나다. 예: `src/content/feed/2026-10-21-<슬러그>.md`
- frontmatter
  - `title` (필수)
  - `date` (필수, 정렬과 표시에 사용)
  - `notionUrl` (필수, URL)
  - `tags` (문자열 배열, 기본값 빈 배열)
  - `image` (선택, 최대 1장. Astro 이미지 처리를 거치도록 `src/assets/feed/` 등에 두고 schema의 `image()` 사용)
  - `imageAlt` (image가 있으면 필수)
  - `draft` (기본 false)
- 본문은 마크다운이며 링크와 줄바꿈을 지원한다(단락·줄바꿈이 화면에 그대로 반영되도록).
- 각 피드는 파일명 기반 id를 가진 앵커(`/feed/#<id>`)로 바로 이동할 수 있다.

## 피드 카드 구성 (위→아래)
1. 작성자 줄: 아이콘 `/favicon2.png`(원형), 이름 `sonny (Son Junhyuck)`, 날짜 `YYYY.MM.DD`(정확한 날짜만, 상대 시간 없음)
2. 제목
3. 내용
4. 사진(있을 때)
5. 태그
6. 원본 Notion 링크 (예: `Notion에서 자세히 보기 ↗`, 새 탭)

## 폭과 레이아웃
- 화면에 보이는 페이지 제목(FEED/피드)과 소개 문구는 두지 않는다. 각 피드에 제목이 있으므로 페이지는 태그 필터와 목록으로 바로 시작한다. 접근성을 위한 페이지 제목(h1)은 시각적으로 숨겨 유지한다. (2026-10-21 추가 합의)
- AGENTS.md의 피드 예외: 페이지 외곽·여백은 공통 기준, 피드 목록은 인스타그램 피드 기준의 좁은 단일 열(약 470px)로 가운데 정렬. 모바일은 화면 폭에 맞춘다.
- 기존 Light·Dark 색상 변수와 타이포그래피를 재사용하고 새 색상은 만들지 않는다(사진 배경의 검은색만 예외).

## 사진 표시 규칙
- 정사각형 영역에 표시한다. 기준 크기는 피드 폭(약 470px).
- 원본의 가로·세로가 모두 기준 크기 이상이면 가운데 기준으로 잘라 꽉 채운다(cover).
- 가로·세로 중 하나라도 기준 크기보다 작으면 자르지도 확대하지도 않고, 원본 전체를 검은 배경(#000) 가운데에 둔다. 테마와 무관하게 검은색.
- 판단은 원본 크기 기준으로 빌드 시 결정해도 된다.
- 빌드 시 적절한 크기의 WebP로 최적화한다.
- 사진을 누르면 원본 전체(잘리지 않은 비율)를 크게 보여 준다. 키보드로 열고 Esc로 닫을 수 있고 닫으면 포커스가 사진으로 돌아온다.

## 불러오기
- 첫 화면에 최신 10개를 HTML로 렌더링한다(JavaScript 없이도 보임).
- 목록 끝에 도달하면 이전 10개씩 이어 붙인다(정적 사이트이므로 빌드 시 묶음 데이터를 생성해 가져오는 방식 등).
- 더 없으면 끝 표시. 불러오기 실패 시 다시 시도할 수 있게 한다.

## 태그 필터
- 사용 중인 태그로 필터 버튼을 만든다(전체 + 태그). 고정 태그 목록은 자동화 단계에서 정하므로 지금은 frontmatter의 태그를 그대로 쓴다.
- 필터는 URL(`?tag=`)로 공유·뒤로가기가 되고, 필터 상태에서도 10개씩 불러오기가 동작한다.

## 예시 데이터
- 사실을 지어내지 않는다. 실제 피드가 없을 때는 빈 상태 문구를 보여 준다.
- 화면 확인용 예시는 `draft: true`로만 두어 프로덕션 빌드에서 제외하고, 개발 서버에서만 보이게 한다. 예시에는 예시임이 드러나는 제목을 쓴다.
- 사진 규칙 확인용 예시 이미지(큰 사진, 둘 다 작은 사진, 한쪽만 작은 사진)가 필요하면 기존 저장소 이미지를 활용한다.
