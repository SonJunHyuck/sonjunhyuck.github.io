# AI와 함께 만든 포트폴리오 웹사이트

> 프로젝트 소개 초안 · 분류 제안: 웹

## 소개

AI와 함께 포트폴리오 웹사이트를 제작하며, 반복되는 수정 기준을 지침과 스킬로 정리하고 변경 범위에 맞는 검증 절차를 마련한 프로젝트입니다.

## 역할과 사용 기술

- 역할: 콘텐츠·화면 구성 결정, 결과 검토, AI 작업 기준 정리
- 사용 기술: Astro · TypeScript · CSS · pnpm
- AI 작업 도구와 기준: Codex · AGENTS.md · SKILL.md · 분야별 매뉴얼

## 구현 및 기여

### 반복되는 판단을 작업 기준으로 정리

콘텐츠와 화면을 검토하며 확정한 기준을 지침과 스킬에 기록했습니다. 같은 설명을 매번 전달하는 부담을 줄이고, 다음 작업에서도 일관된 기준을 참조하도록 구성했습니다.

### 변경 범위에 맞는 검증 절차 구성

문구 수정과 화면·동작 변경의 검증 범위를 구분했습니다. 반복 검사와 과도한 도구 출력이 이어진 경험을 바탕으로, 필요한 확인 범위와 실패 시 중단 기준을 명시했습니다.

### 기여와 구현 의도가 드러나는 콘텐츠 구성

프로젝트의 특징과 제 기여를 구분하고, 구현 의도와 방법에 강조를 적용했습니다. 설명과 관련 이미지·영상을 가까이 배치하며 내용을 검토했습니다.

## 반복되는 피드백을 지침으로 남기기

페이지를 하나씩 수정하면서 같은 판단이 여러 프로젝트에 필요해졌습니다. 프로젝트 특징과 개인 기여를 구분하는 방식, 강조할 문구를 고르는 기준, 구역 사이의 구분선과 미디어 배치 등이 그 예였습니다.

저는 결과물을 검토하고 수정 방향을 결정하면서, **반복해서 적용할 기준을 대화에만 남기지 않고 저장소의 작업 지침에 반영**하도록 했습니다. 공통 원칙은 `AGENTS.md`, 분야별 적용 조건은 `SKILL.md`, 상세 기준과 예외는 매뉴얼로 나누었습니다. 같은 규칙을 여러 문서에 복제하기보다 원본을 참조하도록 정리했습니다.

예를 들어 프로젝트 설명은 결과만 부각하기보다 **왜 개선하려 했고, 어떤 방법을 구현했는지**를 우선해 강조하도록 기준을 세웠습니다. 특정 프로젝트에서 결정한 예외는 해당 프로젝트에 한정해 다른 페이지까지 확대 적용되지 않도록 했습니다.

## 변경 범위에 맞춰 검증하기

작업 과정에서 작은 문구 수정에도 빌드나 화면 확인이 이어지고, 화면 검증 오류를 해결하려는 추가 시도가 반복됐습니다. 긴 문서와 도구 출력까지 다시 읽으면서 토큰 사용이 늘어나는 문제도 경험했습니다.

이를 계기로 **변경한 내용에 필요한 확인만 수행하도록 검증 기준을 구분**했습니다. 의미를 유지한 문구 수정은 변경 차이로 확인하고, 배치나 동작을 바꾼 경우에는 영향을 받는 구간을 검증하도록 했습니다. 화면 크기와 테마를 모든 조합으로 검사하기보다 변경된 속성에 맞는 조건을 선택하도록 정리했습니다.

| 변경 또는 상황 | 정리한 작업 기준 |
| --- | --- |
| 문구·오탈자·지침 수정 | 변경 차이 확인 |
| 배치·스타일·동작 변경 | 변경된 구간과 관련 조건 검증 |
| 이미 통과한 검증 | 새 변경이나 오류 근거가 없으면 결과 재사용 |
| 화면 검증 실패 | 추가 시도를 멈추고 재시도 여부 확인 |
| 파일·로그·화면 정보 조회 | 필요한 구간과 속성만 확인 |

**완료를 확인하기 위한 작업이 불필요한 추가 작업으로 이어지지 않도록**, 중단과 재시도의 기준도 명시했습니다. 검증을 통과했는지와 요청한 의도에 맞는지는 별도로 판단하도록 정리했습니다.

## 마치며

이 프로젝트에서는 화면을 완성하는 과정과 함께, AI에 일을 맡기고 결과를 검토하는 방식도 다듬었습니다. 결과물을 보며 요구사항을 구체화하고, 반복되는 피드백은 다음 작업에서 참고할 수 있는 기준으로 남겼습니다.

지침을 작성했다고 해서 AI가 항상 이를 따르거나 검증 오류가 사라지는 것은 아니었습니다. 따라서 규칙을 추가하는 데서 끝내지 않고 실제 작업이 그 기준에 맞게 진행되는지 확인할 필요가 있었습니다. 앞으로도 **필요한 검증은 유지하면서 불필요한 반복을 줄이는 방향**으로 작업 방식을 개선하고자 합니다.
