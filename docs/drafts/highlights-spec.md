# 하이라이트 페이지 사양 (1차)

2026-11-06 사용자와 Claude가 합의한 내용이다. 구현은 Codex가 맡고 Claude가 검토한다. 기획서: Notion 「🧩 하이라이트 페이지 기획 (초안)」.

## 의도
- 방문자는 긴 상세 페이지를 끝까지 읽지 않는다. 상세의 섹션 하나 분량의 짧은 단위(하이라이트)로 보여 준다.
- 진행 중인 작업도 하이라이트로 먼저 올리고, `프로젝트` 연결로 쌓인 것을 나중에 묶어 프로젝트 상세로 만든다.
- 피드는 하이라이트에 흡수한다. 메뉴는 `프로필 / 하이라이트 / 프로젝트 / 개발일지 ↗`.

## 주소와 정리
- 주소는 `/highlights/`. 기존 `/feed/`는 외부 공유 이력이 없어 연결 페이지 없이 삭제한다.
- 피드 컬렉션·페이지·스크립트는 하이라이트로 옮기거나 삭제한다. 사이트맵 갱신.

## 데이터 (`src/content/highlights/*.md`)
- `title`(필수), `date`(필수), `summary`(카드 한 줄, 선택 — 없으면 본문 첫 줄을 말줄임), `tags`(고정 주제 태그 목록에서 최대 2개), `project`(선택, 프로젝트 id), `image`·`imageAlt`(선택), `lettering`(썸네일 큰 글자, 2~8자 권장), `notionUrl`(선택), `draft`.
- 상세 섹션에서 가져오는 하이라이트: `source: { project, section }`을 두고 본문은 비운다. 빌드 시 해당 프로젝트 상세의 그 섹션 내용을 그대로 가져와 표시한다(원본 하나, 상세를 고치면 함께 바뀜). 날짜는 그 프로젝트 기간의 끝 달.
- 기존 피드 글 15개는 본문·태그·사진·notionUrl을 그대로 옮긴다.
- 주제 태그 목록은 기존 피드 태그를 잇는다(`src/config`의 단일 원본). `project`가 있으면 '프로젝트: 이름' 태그를 자동으로 붙이고 강조 표시한다.

## 목록 화면
- 화면에 보이는 제목·소개 없이 태그 필터 한 줄(가로 스크롤, 글 수 순) → 카드 그리드. 접근성용 h1은 숨김. 필터에는 프로젝트 태그도 포함.
- 카드: 데스크톱 한 행 2개, 모바일 1개. 16:9 썸네일 → 제목 → 한 줄 요약 → 태그 → 날짜. 카드 구역은 규격화해 같은 줄 정렬.
- 썸네일: 이미지 위에 `lettering`을 크게 얹은 정보 유튜브 썸네일 형식. 이미지는 가공하지 않고 글자만 얹는다(HTML 오버레이 — 가독성용 테두리·그림자만). 이미지가 없으면 사이트 색 변수의 단색 배경에 같은 레터링.
- 최신순. 처음 10개, 끝에 닿으면 10개씩 더(기존 피드 방식).

## 미리보기
- 카드를 누르면 상세로 가지 않고 미리보기 창(기존 프로젝트 미리보기 창 패턴). 이미지 위, 태그·날짜·제목, 본문 전체(섹션 하나 분량), 하단에 '이 프로젝트 전체 보기 →'(프로젝트 상세가 있을 때), 'Notion에서 자세히 보기 ↗'(notionUrl이 있을 때).
- 창 양옆 이전·다음 버튼, 위치 표시(예: 3 / 12)는 현재 필터 결과 기준. 데스크톱 ←/→, 모바일 좌우 스와이프. 모바일은 아래 시트.
- 주소 `?h=<id>`로 공유·뒤로 가기, `?tag=`와 공존. Esc·닫기·바깥·뒤로 가기로 닫고 포커스 복귀.

## 흐름
- 슬라이드인 행선지: 프로필 → 하이라이트 → 프로젝트 목록 → 프로필, 프로젝트 상세 → 다음 프로젝트, 회고 → 프로필 업무 경험. 하이라이트는 모두 불러온 뒤에만.
- 프로필 하단 버튼: '하이라이트 구경하기 →', '프로젝트 구경하기 →'.
