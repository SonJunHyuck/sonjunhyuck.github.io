# 작성·검수·배포 체크리스트

현재 작업에 해당하는 절과 항목만 적용합니다. 검증 여부·범위·생략 기준은 [AGENTS.md](../AGENTS.md)를 따릅니다. 병합·배포는 요청 범위에 포함된 경우에만 수행합니다.

## 새 프로젝트

- [ ] 공개해도 되는 프로젝트명, 역할, 기간, 결과인지 확인했다.
- [ ] 독자가 이해할 문제와 나의 기여를 첫 화면에 명확히 적었다.
- [ ] 결과 수치·인용·이미지의 근거와 사용 권한을 확인했다.
- [ ] 대표 이미지와 모든 의미 있는 이미지에 적절한 대체 텍스트를 넣었다.
- [ ] 관련 글·저장소·데모로 이어지는 링크를 검증했다.
- [ ] URL 슬러그, 제목, 설명, 태그, 공개 상태를 콘텐츠 스키마에 맞게 작성했다.

## 새 개발 글 (Notion DevLog)

- [ ] 제목과 요약이 글에서 답하는 질문을 분명히 설명한다.
- [ ] 전제 조건, 사용 환경, 버전 또는 날짜를 적었다.
- [ ] 코드와 명령은 복사 가능한 형태이며 결과 또는 주의점을 함께 제공한다.
- [ ] 출처, 인용, 외부 링크의 정확성과 권한을 확인했다.
- [ ] 관련 기존 글에 연결하는 내부 링크를 추가했다.
- [ ] 맞춤법, 용어, 제목 계층, 이미지 대체 텍스트를 검토했다.

## 병합 전

- [ ] 작업 브랜치에서 변경 내용을 읽고 불필요한 파일·비밀값이 없는지 확인했다.
- [ ] 배치·반응형 변경이 있다면 관련 구간의 데스크톱·모바일 화면을 확인했다.
- [ ] 빌드가 필요한 변경이면 변경을 모은 뒤 한 번 실행해 성공을 확인했다.
- [ ] 링크·이미지·코드 블록·404 중 실제 변경한 대상만 점검했다.
- [ ] Pull Request에 목적, 사용자 영향, 검증 방법을 적었다.
- [ ] 별도 검토가 필요한 작업이면 검토를 받았고 미해결 의견이 없다.

## 배포 후

- [ ] GitHub Actions 배포가 성공했다.
- [ ] 변경된 공개 경로에서 배포 반영을 확인했다.
- [ ] 배포 환경 차이나 오류 징후가 있으면 해당 항목만 추가 확인했다.
- [ ] 오류가 있으면 이슈와 후속 조치를 남겼다.

## Pull Request 설명에 포함할 내용

```md
## 목적

<!-- 왜 이 변경이 필요한가? -->

## 변경 내용

<!-- 콘텐츠, UI, 설정의 핵심 변경 -->

## 확인 방법

<!-- 실행한 빌드/화면/링크 확인 -->

## 배포 영향

<!-- URL, 리디렉션, 메타데이터, 사용자 영향. 없으면 없음 -->
```
