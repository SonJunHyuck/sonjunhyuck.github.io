# 레이아웃 기준

실제 수치와 색상의 단일 원본은 [global.css](../../../../src/styles/global.css)다. 값이 필요할 때 해당 선언만 확인한다. 공통 폭과 예외 정책은 [AGENTS.md](../../../../AGENTS.md)를 따른다.

## 폭과 흐름

- 상세 페이지에서 독립된 구역으로 넘어가는 경계(섹션·기능·마무리 글)에는 공통 `--line` 구분선을 사용한다. 기능 순서를 바꾸거나 섹션을 삭제해도 인접 구역 사이의 선이 유지되도록 구조를 기준으로 적용하며, 특정 기능 ID로 선을 없애지 않는다. 본문 시작 경계의 선은 중복하지 않고, 같은 구역 안의 소제목은 제외한다. 세부 여백은 공통 스타일에서 관리한다.

## 색상 역할

Light는 Apple, Dark는 Spotify를 참고한 이 사이트의 팔레트다.

| 역할·변수 | 사용 |
|---|---|
| `--paper` | 페이지 바탕 |
| `--ink` | 제목과 주요 글자 |
| `--accent` | 링크·핵심 강조·선택 상태 |
| `--muted` | 설명·날짜·메타데이터 |
| `--surface` | 카드·컨트롤 배경 |

- 본문·버튼·배지·포커스는 CSS의 해당 의미별 변수를 쓴다. 강조색을 모든 버튼 글자에 일괄 적용하지 않는다.
- 버튼은 `--button-bg`와 `--button-text`, 표면 위 강조 글자는 `--accent-ink`, 포커스는 `--focus`처럼 기존 대비 조합을 사용한다.

## 화면 검증 범위

검증 필요 여부와 영향 범위는 AGENTS.md로 판단하고 다음 방법을 적용한다.
- 기존 앱 내 브라우저 세션을 우선 재사용하며, 별도 Chrome이나 외부 브라우저를 임의로 실행하지 않는다.
- 문구·링크·필터는 대상 locator의 텍스트·주소·개수, 색상·간격·넘침은 계산된 스타일과 크기를 조회한다. 도구의 필수 초기 확인 이후에는 긴 본문 전체의 DOM·접근성 트리·outerHTML을 출력하지 않는다. 필수 상태 갱신은 원문 출력을 억제하거나 결과를 재사용한다.
- 시각 확인이 필요한 구간만 캡처하고 한 장으로 확인 가능한 변경은 함께 확인한다. 같은 상태의 DOM 전체와 스크린샷을 연달아 수집하지 않는다. 전체 캡처는 전체 흐름·레이아웃 변경에만 사용하며, 사용자 요청이나 도구의 필수 조건 없이 완료 보고용 캡처를 추가하지 않는다.
- 예: 카드 배치와 색상이 바뀌면 배치는 데스크톱·모바일, 색상은 한 크기의 Light·Dark에서 확인한다. 반응형과 테마가 연동되지 않으면 네 조합을 모두 촬영하지 않는다.

## 탐색 메뉴

- 상단 프로젝트 링크를 클릭하면 전체 프로젝트로 이동한다. 업무경험·게임·연구 하위 메뉴는 hover와 키보드 focus에서 가로로 표시한다. 터치 환경에서도 상위 링크 이동과 하위 링크 접근을 함께 보장한다.
- 탐색 메뉴 정렬은 요소 사각형만 비교하지 않고 실제 글자 범위와 확대 화면에서 기준선을 확인한다. 활성 표시가 링크 높이를 바꾸지 않도록 밑줄 공간을 동일하게 확보한다.

## 프로젝트 상세 상단

- 모든 상세의 돌아가기 링크는 `← 돌아가기` 문구로 `/projects/`에 연결한다. 분류별 복귀는 사용하지 않는다.
- 돌아가기 링크의 클릭 영역과 제목·분류 문구까지의 간격은 상세 공통 템플릿에서 관리하며 프로젝트별로 재정의하지 않는다.
- 프로젝트 필터와 돌아가기 링크는 공통 컨트롤 스타일로 크기·패딩·테두리·모서리·일반 글자 두께를 통일한다. hover는 강조색, 선택된 필터는 버튼 대비 조합, 키보드 포커스는 포커스 변수를 사용한다.
