# 레이아웃 기준

실제 수치와 색상의 단일 원본은 [global.css](../../../../src/styles/global.css)다. 값이 필요할 때 해당 선언만 확인한다. 공통 폭과 예외 정책은 [AGENTS.md](../../../../AGENTS.md)를 따른다.

## 폭과 흐름

- 상세 페이지에서 독립된 구역으로 넘어가는 경계(섹션·기능·마무리 글)에는 공통 `--line` 구분선을 사용한다. 기능 순서를 바꾸거나 섹션을 삭제해도 인접 구역 사이의 선이 유지되도록 구조를 기준으로 적용하며, 특정 기능 ID로 선을 없애지 않는다. 본문 시작 경계의 선은 중복하지 않고, 같은 구역 안의 소제목은 제외한다. 세부 여백은 공통 스타일에서 관리한다.

## 색상 역할

Light는 Apple, Dark는 Spotify를 참고한 이 사이트의 팔레트다.

포트폴리오 웹사이트 프로젝트의 테마 비교 견본은 사용자가 승인한 예외로, 현재 페이지 테마와 무관하게 각 박스에 실제 Light·Dark 공통 팔레트를 고정 적용한다. 이 예외는 해당 프로젝트의 테마 비교에만 적용한다.

| 역할·변수 | 사용 |
|---|---|
| `--paper` | 페이지 바탕 |
| `--ink` | 제목과 주요 글자 |
| `--accent` | 링크·핵심 강조·선택 상태 |
| `--muted` | 설명·날짜·메타데이터 |
| `--surface` | 카드·컨트롤 배경 |

- 본문·버튼·배지·포커스는 CSS의 해당 의미별 변수를 쓴다. 강조색을 모든 버튼 글자에 일괄 적용하지 않는다.
- 버튼은 `--button-bg`와 `--button-text`, 표면 위 강조 글자는 `--accent-ink`, 포커스는 `--focus`처럼 기존 대비 조합을 사용한다.

## 화면 검증 범위

검증 필요 여부와 영향 범위는 AGENTS.md로 판단하고 다음 방법을 적용한다.
- 기존 앱 내 브라우저 세션을 우선 재사용하며, 별도 Chrome이나 외부 브라우저를 임의로 실행하지 않는다. 단, 캡처는 앱 내 브라우저가 없거나 지정 폭·전체 페이지 캡처가 필요할 때 Headless Chromium(Chrome 헤드리스 모드)으로 해도 된다(2026-11-05 사용자 허용).
- 문구·링크·필터는 대상 locator의 텍스트·주소·개수, 색상·간격·넘침은 계산된 스타일과 크기를 조회한다. 도구의 필수 초기 확인 이후에는 긴 본문 전체의 DOM·접근성 트리·outerHTML을 출력하지 않는다. 필수 상태 갱신은 원문 출력을 억제하거나 결과를 재사용한다.
- 시각 확인이 필요한 구간만 캡처하고 한 장으로 확인 가능한 변경은 함께 확인한다. 같은 상태의 DOM 전체와 스크린샷을 연달아 수집하지 않는다. 전체 캡처는 전체 흐름·레이아웃 변경에만 사용하며, 사용자 요청이나 도구의 필수 조건 없이 완료 보고용 캡처를 추가하지 않는다.
- 사용자에게 전달하거나 Notion 등에 남길 캡처는 개발 서버가 아닌 배포 빌드(preview)에서 찍는다. 개발 서버에는 Astro 개발 도구 막대가 화면 하단에 겹친다.
- 예: 카드 배치와 색상이 바뀌면 배치는 데스크톱·모바일, 색상은 한 크기의 Light·Dark에서 확인한다. 반응형과 테마가 연동되지 않으면 네 조합을 모두 촬영하지 않는다.

## UI/UX 자체 검토

화면을 검토할 때 지시받은 항목만 보지 않고, 처음 보는 방문자 기준으로 읽기 흐름·구획·정렬·간격·위계가 어색한 곳(예: 성격이 다른 구역 사이 구분선 누락, 정렬 어긋남)을 함께 찾는다(2026-11-05 사용자 지시).
- 기존 기준 안에서 판단이 분명한 수정은 사용자에게 묻지 않고 한두 번의 수정 범위에서 바로 반영하고, 반영 사실을 보고한다.
- 공통 기준(색·폭·페이지 구성 원칙)을 바꾸거나 취향이 갈리는 판단은 추천안과 함께 사용자에게 묻는다.

## 탐색 메뉴

- 사이트 첫 화면(`/`)은 대분류 카드 랜딩이며 프로필은 `/profile/`이다([랜딩 사양](../../../../docs/drafts/landing-spec.md)).
- 상단 메뉴는 `프로필 / 하이라이트 / 프로젝트 / AI 협업 / 개발일지 ↗` 순서다(2026-11-06 피드를 하이라이트로 흡수, 2026-11-10 AI 협업 분리). 하이라이트(`/highlights/`)와 개발일지(Notion 새 탭)는 별개로 함께 유지한다. 하이라이트 화면 세부 기준은 [하이라이트 사양](../../../../docs/drafts/highlights-spec.md)을 따른다.
- 상단 프로젝트 링크를 클릭하면 전체 프로젝트로 이동한다. 분류 하위 메뉴는 hover와 키보드 focus에서 가로로 표시한다. 분류 동기화 기준은 [목록 매뉴얼](../../portfolio-project/references/list.md)을 따른다. 터치 환경(hover 불가)에서는 하위 메뉴를 표시하지 않고, 상위 링크로 전체 프로젝트에 이동해 페이지의 분류 필터로 접근한다(2026-10-27 변경: 모바일에서 하위 메뉴가 항상 펼쳐져 보이던 문제).
- 탐색 메뉴 정렬은 요소 사각형만 비교하지 않고 실제 글자 범위와 확대 화면에서 기준선을 확인한다. 활성 표시가 링크 높이를 바꾸지 않도록 밑줄 공간을 동일하게 확보한다.

## 페이지 간 흐름

방문자가 흐름을 잃지 않게 페이지 끝마다 다음 행선지를 제공한다(2026-11-05). 좌우 화살표 이정표는 쓰지 않는다.
- 하단 슬라이드인 카드: 푸터가 보이면 다음 행선지 카드를 작게 띄우고(데스크톱 오른쪽 아래, 모바일 아래 폭 맞춤), 위로 올리면 숨긴다. 닫으면 그 페이지에서 세션 동안 다시 띄우지 않는다. 행선지는 프로필 → 하이라이트 → 프로젝트 목록 → AI 협업 → 프로필, 프로젝트 상세 → 같은 대분류 안의 다음 프로젝트(마지막이면 처음으로 순환), 회고 → 프로필 업무 경험. 하이라이트는 모든 글을 불러온 뒤에만, 미리보기 창이 열려 있으면 숨긴다.
- 프로젝트 상세 끝에는 소속 대분류 목록으로 가는 링크와 '다음 프로젝트: 이름 →'를 둔다. 상단 돌아가기도 소속 대분류 목록으로 간다.
- 사이트 내부 이동 표시는 →, 외부·새 탭 링크는 ↗를 쓴다.

## 프로젝트 상세 진행 게이지

- 상세 머릿말(제목·요약·대표 이미지·메타)과 본문 사이에 진행 게이지를 두고, 스크롤하면 사이트 헤더 아래에 붙는다(2026-11-05). 읽은 만큼 강조색으로 채우고 끝에 작은 캐릭터가 따라 이동한다(움직임 줄이기 설정이면 정지).
- 본문 섹션(h2, h2가 3개 미만이면 h3까지) 위치에 눈금을 두고 눈금 아래에 섹션 제목을 작은 회색 글자로 표시한다. 눈금·제목을 누르면 이동한다. 게이지 길이가 변하지 않도록 옆에 목차 버튼을 두지 않는다. 모바일은 현재 섹션 이름만 표시하고 게이지를 누르면 섹션 목록을 펼친다.

## 프로젝트 상세 상단

- 모든 상세의 돌아가기 링크는 `← 돌아가기` 문구로 `/projects/`에 연결한다. 분류별 복귀는 사용하지 않는다.
- 돌아가기 링크의 클릭 영역과 제목·분류 문구까지의 간격은 상세 공통 템플릿에서 관리하며 프로젝트별로 재정의하지 않는다.
- 프로젝트 필터와 돌아가기 링크는 공통 컨트롤 스타일로 크기·패딩·테두리·모서리·일반 글자 두께를 통일한다. hover는 강조색, 선택된 필터는 버튼 대비 조합, 키보드 포커스는 포커스 변수를 사용한다.
